# readd

Домашняя библиотека аудиокниг: загрузка книг папками, плеер с сохранением прогресса,
общая и личная библиотеки, статистика. Плюс озвучка epub через внешний TTS-сервер
(в разработке).

- `server/` — бэкенд на Rust (Axum, SQLx, SQLite). Он же раздаёт собранный фронтенд и файлы книг.
- `frontend/` — веб-интерфейс на Vue 3 (Vite, TanStack Query).

## Запуск в Docker

```bash
docker compose up -d          # образ ghcr.io/fess932/readd:latest
docker compose up -d --build  # или собрать из исходников
```

Откройте http://localhost:3000. База и все файлы книг лежат в папке `./data` рядом с `compose.yml` (`/data` в контейнере).
Порт, папка данных и адрес TTS-сервера правятся прямо в `compose.yml`; свой секрет для токенов
задаётся переменной `JWT_SECRET` в окружении или в файле `.env` (см. [.env.example](.env.example)).

Вход — по имени, без пароля; пользователь `admin` получает права администратора.
Сервис рассчитан на домашнюю сеть, наружу его выставлять не стоит.

Образ собирается в GitHub Actions при каждом пуше в `main` (тег `latest`) и для тегов `v*`.

## Разработка

Нужны [Rust](https://rustup.rs) и [Bun](https://bun.sh); для озвучки epub — ещё `ffmpeg` в `PATH`.

```bash
bun install
bun run dev      # сервер на :3000 и Vite на :5173 с горячей перезагрузкой
bun run test     # тесты сервера и проверка типов фронтенда
bun run build    # dist/ и релизный бинарник server/target/release/readd-server
bun run start    # запустить релизную сборку (отдаёт dist/)
```

Сервер читает из окружения `DATABASE_URL`, `UPLOADS_DIR`, `DIST_DIR`, `JWT_SECRET`,
`TTS_SERVER_URL`, `HOST`, `PORT`, `RUST_LOG` — у всех есть значения по умолчанию,
пути считаются от текущего каталога. `bun run dev` запускает его из корня репозитория:
база `readd.db` и каталог `uploads/` появятся там же.

### Запросы и миграции

Схема базы — в `server/migrations/`, сервер применяет миграции сам при старте.
Уже применённые миграции не редактируются: любое изменение — новым файлом.

SQL-запросы проверяются при компиляции по кэшу `server/.sqlx/`, который лежит в репозитории,
поэтому для сборки база не нужна. После изменения запроса или миграции кэш надо обновить:

```bash
cd server
export DATABASE_URL=sqlite:/tmp/readd-dev.db
cargo sqlx database create && cargo sqlx migrate run   # нужен sqlx-cli
cargo sqlx prepare
```

Кэш собирается по свежей базе, а не по рабочей `readd.db`: у старых баз другая история
создания таблиц, и типы колонок выводятся иначе.

### Озвучка epub

Фоновый воркер режет текст книги на фрагменты и по одному отправляет их на
`POST {TTS_SERVER_URL}/synthesize` с телом `{"text": "..."}`; в ответ ожидается аудио
(формат берётся из `Content-Type`). Готовые фрагменты склеиваются через `ffmpeg` в один M4B
с главами, и книга появляется в общей библиотеке. Пока сервер недоступен, задача ждёт;
если он трижды отверг один фрагмент, задача останавливается с ошибкой, и её можно повторить.
